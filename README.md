# Balatro Joker Tier List

Balatro 조커 150장을 S·A·B·C·D·F 티어로 정리하는 비공식 팬 제작 웹 앱입니다.
한국어 조커 정보, 검색·필터, 드래그 재배치, 티어별 코멘트와 JSON 저장 파일을 지원합니다.

## 바로 실행

### 웹에서 사용

저장소 관리자가 GitHub Pages를 활성화했다면 저장소의 **About → Website** 링크를 열면 됩니다.
회원가입, 프로그램 설치, 별도 서버 접속 설정은 필요하지 않습니다.

### 다운로드해서 사용

1. GitHub 저장소에서 **Code → Download ZIP**을 선택합니다.
2. ZIP 파일을 **전부 압축 해제**합니다. 압축파일 안에서 HTML만 열지 마세요.
3. 압축을 푼 폴더의 **`index.html`**을 브라우저로 엽니다.

`index.html`, `app.js`, `styles.css`, `data/`, `assets/`를 함께 보관하세요.
앱 실행에는 Python, Node.js, npm이나 추가 패키지 설치가 필요하지 않습니다.
외부 CDN에 의존하지 않으며, 포함된 데이터와 이미지로 오프라인 실행이 가능합니다.

## 주요 기능

- S부터 F까지 조커 분류, 같은 티어 안의 순서 변경, 드롭 위치와 순번 표시
- 이름·효과 검색, 희귀도·특성 필터, 검색 결과의 첫 조커 자동 선택
- 조커 효과·희귀도·가격·해금 정보와 티어별 짧은 코멘트
- 미분류 목록 정렬 및 드래그 시 사용자 지정 순서 유지
- 브라우저 자동 저장, JSON 내보내기·가져오기
- 플레이 통계가 포함된 버전에서는 **데이터 대조하기**로 사용 횟수 표시/숨김

## 저장과 백업

처음 접속하거나 브라우저에 저장된 배치가 없으면 제작자의 기본 티어리스트를 불러옵니다.
조커 순서와 티어별 코멘트도 포함됩니다. 이미 저장된 배치가 있으면 방문자의 저장 내용을 우선하며 자동으로 덮어쓰지 않습니다.
기존 방문자는 새로고침만으로 기본 배치로 바뀌지 않습니다. 초기화 버튼은 모든 조커를 미분류로 옮기는 기존 동작을 유지합니다.

티어 배치와 코멘트는 사용 중인 브라우저의 `localStorage`에 저장됩니다.
서버나 GitHub에 자동으로 업로드되지 않으며 다른 사용자와 공유되지 않습니다.

- 중요한 작업은 상단 **내보내기** 버튼으로 JSON 파일을 보관하세요.
- **가져오기** 버튼으로 내보낸 JSON을 복원할 수 있습니다.
- 브라우저 데이터 삭제, 시크릿 모드 종료, 다른 브라우저 사용 시 저장 내용이 유지되지 않을 수 있습니다.
- 로컬 파일, `localhost`, `127.0.0.1`, GitHub Pages 주소의 저장 공간은 서로 다를 수 있습니다. 이동할 때는 내보내기·가져오기를 사용하세요.
- 로컬 파일의 자동 저장은 브라우저 정책에 따라 제한될 수 있습니다. JSON 백업을 권장합니다.

## 개인 플레이 통계

공개용 패키지는 개인 플레이 통계와 원본 티어 저장 파일을 제외합니다. 제작자가 공개한 기본 배치만 `data/default-tier-list.js`에 포함합니다.
이 경우 `data/joker-usage.js`에는 빈 데이터만 들어 있고 **데이터 대조하기** 버튼은 비활성화됩니다. 일반 티어 분류는 정상 동작합니다.

통계를 포함한 버전의 오버레이는 조커별 `count`(사용 횟수)를 표시합니다.
`wins`의 마지막 숫자는 승리 횟수로 보관되며, 현재 오버레이에는 표시하지 않습니다.
게임 내부 이름을 영문명과 별칭 대응표로 연결합니다. 게임의 `order`와 앱의 목록 번호는 다르므로 번호만으로 연결하지 않습니다.
기록이 없으면 `-`, 실제 사용 횟수가 0이면 `0`을 표시합니다.

**주의:** 저장소나 배포 파일에 포함한 통계와 JSON 저장 파일은 공개될 수 있습니다.
가져오기 기능으로 브라우저에 불러온 티어 배치는 서버로 전송되지 않습니다.

## GitHub Pages 배포

별도의 빌드 명령이나 GitHub Actions 설정 파일 없이 정적 파일을 배포할 수 있습니다.

1. 아래 파일 구조가 **저장소 최상위**에 오도록 업로드합니다. ZIP 파일 자체만 올리면 앱이 실행되지 않습니다.
2. 저장소의 **Settings → Pages**로 이동합니다.
3. **Build and deployment → Source → Deploy from a branch**를 선택합니다.
4. 파일을 올린 브랜치(예: `main`)와 **`/(root)`**를 선택한 뒤 **Save**를 누릅니다.
5. 배포가 완료되면 Pages 설정의 **Visit site**로 접속합니다. 이 주소를 저장소 About의 Website에도 등록하면 사용자가 찾기 쉽습니다.

프로젝트 사이트의 주소 형태는 `https://사용자명.github.io/저장소명/`입니다.
GitHub Free에서는 공개 저장소로 Pages를 사용할 수 있습니다. 비공개 저장소 지원 여부는 계정 요금제에 따라 다릅니다.
설정 절차는 [GitHub Pages 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)를 참고하세요.

```text
repository/
  index.html
  app.js
  styles.css
  README.md
  .gitignore
  .nojekyll
  data/
    jokers.json
    jokers.js
    joker-usage.json
    joker-usage.js
    default-tier-list.js
  assets/
    jokers/
      ... 150 image files
```

`jokers.json`은 웹 주소에서, `jokers.js`는 로컬 파일 실행 시 사용합니다.
`.nojekyll`은 GitHub Pages에 정적 파일을 그대로 게시하기 위한 파일입니다.

## 실행 문제 해결

| 증상 | 확인할 사항 |
| --- | --- |
| 조커가 보이지 않음 | ZIP을 전부 풀었는지, `data/`와 `assets/` 폴더가 있는지 확인하세요. |
| 변경 사항이 보이지 않음 | 새로고침하고, 필요하면 `Ctrl+Shift+R`로 캐시를 갱신하세요. |
| 자동 저장이 안 됨 | 브라우저 저장 제한을 확인하고, 내보내기로 작업을 보관하세요. |
| 대조 버튼이 비활성화됨 | 개인 플레이 통계를 제외한 버전에서는 정상입니다. |
| GitHub Pages가 404를 표시함 | 선택한 브랜치의 최상위에 `index.html`이 있는지, Pages 배포가 완료됐는지 확인하세요. |

로컬 파일 실행이 제한된 환경에서 Python이 이미 설치돼 있다면, 앱 폴더에서 아래 명령으로 로컬 서버를 사용할 수도 있습니다.

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8000/`을 열고, 사용을 마치면 터미널에서 `Ctrl+C`로 종료합니다.
8000 포트를 사용 중이면 다른 포트 번호로 바꿔 실행하세요.
